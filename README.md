# Ally Programming Language

## 設計思想
1. 「暗黙な処理」ではなく、「明示的な処理」
Rustを含む多くの現代の言語は、=と書くと、コンパイラがmove, copyを切り替えます。
しかし、Allyでは、これをシステムプログラミングにおける不透明性だと感じ、
    - **所有権の可視化**: `<-`(ムーブ)と、`=`(コピー)を分けることで、メモリの動き、計算量をコード上で完全に可視化します。
    - **制御フローからの明確化**: 関数の戻り値を`ret = value`や、`ret <- value`という代入形式にすることで、どの値がいつ返されるのかを、一目で判別可能にします。
2. 「不合理な制限」からの解法
Rustで使われる従来のボローチェッカー(NLL)は、時として人間には絶対に安全だとわかるコードもエラーになります。
これは、コンパイラの「生存期間」の考え方が、人間の論理的な直観よりも不器用であるためです。
    - **Simplified Polonius**: Allyは、生存期間を「グラフ上の範囲」ではなく、**「ポイントベースの借用集合(Bitset)」**として扱います。
    - **直観に沿った安全性**: `get_or_insert`問題に代表される、条件分岐を伴う、複雑な参照の受け渡しを自然に記述できます。「ボローチェッカーと戦う」時間を最小化し、ロジックの本質に集中できる環境を提供します。
3. 「高いパフォーマンス」
Allyは、実行時のオーバーヘッドを一切排除します。
    - **ゼロコスト抽象化**: ガベージコレクションを持たず、コンパイル時の性的解析によってメモリ安全性を保証します。
    - **コンパイル速度の維持**: フルPoloniusの計算量を、ポイントベースのビットセットアルゴリズムに凝縮することで、高い解析制度と、実用的なコンパイル時間を両立させます。
    - **comptime計算**: 内部のVMを使い、コンパイル時に計算できるものは定数として畳みこむことで、実行時の計算量を軽減させます。

## この言語の特徴
### 解決される[get_or_insert問題]
Rustでは条件分岐によって借用を返却する際、ボローチェッカーの制限で不必要なエラーがでることがありますが、Allyのビットセット解析は、パスごとの生存期間を正確に追跡します。
```ally
fn get_or_insert(map: &mut Map, key: i32) -> &mut string {
    let res = map.get_mut(key);
    if res != None {
        ret <- res.unwrap();
    }
    map.insert(key, "");
    ret <- map.get_mut(key).unwrap();
}
```
### 明示的な所有権操作
Allyでは、値がムーブか、コピーかを曖昧にしません。
- `<-`: Move(所有権の移動)。元の変数は使用不可になります。
- `=`: Copy(値の複製)。元の変数は使用可能です。しかし、プリミティブ型などの軽い型のみにしか使用できません。(<- hoge.clone()としてください)
```ally
let s1 <- 10;
let s2 = s1; // コピーなので、s1は使える
let s2 <- s1; // これ以降s1は使えない
ret <- s2;
```
(注): 文法は現時点で正確に決まっておりません。このコードと文法が異なる可能性があります。
### 明示的なリターン構文(ret)
関数の戻り値は`ret`キーワードを用いて代入形式で記述します。これにより、式の終わりと関数の終わりを混同するミスを防ぎます。
```ally
fn add(a: int, b: int){
    ret = a + b;
}
```


## なぜ簡易Poloniusなのか
Rustの標準的なNLL(Non-Lexical Lifetimes)は、ライフタイムを「グラフ上の範囲」として扱います。これは計算が高速ですが、特定の条件分岐において、正しいコードを間違えて指摘することが多くあります。
Allyの採用する**ポイントベース・ビットセット方式**は、各プログラム地点において、「どの借用(LoanId)が有効か」をビットセットで管理します。
- **計算量**: データフロー解析により、NLLと同党の実用的な速度で動作。
- **精度**: フルPoloniusに近い解析精度を持ち(フルPoloniusには劣ります)、条件分岐をまたぐ借用を正確に処理します。

## ライセンス
### Ally Compiler
Allyコンパイラ本体のソースコードは**GPL v3.0** ライセンスの下で公開されています。コンパイラ自体を改造・再配布する場合は、そのソースコードを公開し、GPLライセンスを継承する必要があります。
### Compiler Output
Allyコンパイラによって出力されたバイナリや実行ファイルやログは**CC0**ライセンスを適用しています。
出力物に関しては、商用・改変・配布などすべて自由です。永遠に無条件で、私の許可も必要ありません。ただし、それによって起きたことへの責任は私は全く負いません。
### Runtime & Standard Library
コンパイラがバイナリに注入するランタイムコード及び、標準ライブラリ(`libally`, `stdlib`など)については、**CC0**ライセンスを適用しています。これにより、生成されたバイナリを配布する際に、GPLの制約を受けることはありません。
